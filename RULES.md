# How the ESLint rules carried over

This package used to be an ESLint config. Every plugin and rule it enforced is still enforced, now
through Oxlint. Most rules run on Oxlint's own Rust implementations. The rest run through Oxlint's
JS plugin support, which loads the original ESLint plugin.

## Native plugins

ESLint core, TypeScript (including type-aware rules), React, jsx-a11y, Unicorn and Import run on
Oxlint's native plugins, with the same severities and options the ESLint config used. The list came
from `@oxlint/migrate`, checked rule by rule.

## JS plugins

These ESLint plugins run as they are, pinned to exact versions in `package.json`, because Oxlint's
JS plugin support is still alpha:

| Plugin                          | Config           | Rules                                                          |
| ------------------------------- | ---------------- | -------------------------------------------------------------- |
| `eslint-plugin-perfectionist`   | `base.json`      | the `recommended-alphabetical` preset, import sorting included |
| `eslint-plugin-testing-library` | `testing.json`   | the `flat/react` preset, on test and story files               |
| `eslint-plugin-storybook`       | `storybook.json` | the `flat/recommended` preset                                  |
| `eslint-plugin-typedoc`         | `typedoc.json`   | the `recommended` preset                                       |

## Rules Oxlint has no native version of yet

Unicorn and React both have native plugins, but some of their rules aren't in them. Those rules run
from the original plugin under an alias, `unicorn-js` and `react-js`, so they don't clash with the
native plugin's names. The React ones only run on `.jsx` and `.tsx` files. When Oxlint adds a native
version, the rule moves back to the native plugin.

## What changed on purpose

- `prettier/prettier` is gone: oxfmt does the formatting, with settings that print what Prettier
  printed (see the README).
- Two house rules are new: `import/no-default-export` (named exports; config, story and `.d.ts`
  files are exempt) and `eslint/no-restricted-imports` against `../../../` imports (use a path
  alias).
- `unicorn/filename-case` keeps its `__tests__`-style exception, written as a string pattern
  because Oxlint takes patterns as strings.
